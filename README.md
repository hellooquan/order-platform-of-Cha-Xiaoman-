# 茶小满 · 奶茶点餐系统

> 项目类型:Linux 网络编程 + LVGL 嵌入式界面课程综合项目(点餐机 / 商家后台 / 服务端 三端一体)
> 开发环境:WSL(Ubuntu)+ LVGL 9.2 + SDL2 模拟器,CMake 多目标构建

---

## 1. 设计目标

模拟真实奶茶门店的数字化点餐场景:顾客在触摸屏点餐机点单,商家在后台调价并监控订单,
服务端汇总订单落盘存档。三个角色通过"TCP + 共享数据文件"解耦协作。

1. **网络编程**:掌握 Linux 下 BSD s ocket(TCP)通信与多线程并发模型;
2. **图形界面**:掌握 LVGL 嵌入式 UI 开发(SDL2 模拟器调试,可移植真机);
3. **多程序协作**:client / admin / server 三端共享一份工程与构建,体验模块划分与资源复用;
4. **工程化**:CMake 单工程多 target、数据与代码分离、路径宏集中管理。

## 2. 功能描述

本系统两个图形端(client 点餐机、admin 商家后台)均为 1024×600 触摸界面;server 为
纯后台程序,没有界面,功能见 4.1。界面功能按端描述如下。

### 2.1 点餐机(client)

- **界面布局**:奶油色渐变背景,单屏展示。顶部为品牌栏(「茶」logo、品牌名、
  右上角"第二杯半价 · 今日特惠"特惠条);中部 5 张招牌饮品卡片横向排布;底部为
  白色汇总条(左侧店名、中间合计、右侧"提交订单"按钮)。
- **饮品卡片**:每张卡片含一张用 LVGL 图形绘制、随饮品主题色变化的奶茶杯插画,
  下方是中文名、卖点与英文名,右上角标出单价;卡片整体可点击。
- **点选饮品**:点击卡片即 +1 杯,卡片右上角弹出红色数量角标实时显示已点杯数;
  卡片上的"−"可减杯,数量为 0 时"−"自动置灰,不可再减。
- **实时合计**:底部汇总条随加减杯即时刷新,显示已选总杯数与按当前单价计算的合计金额。
- **提交订单**:点"提交订单"送出本次所选;未点任何饮品时点提交无效;提交成功后
  已选数量自动清零、角标与合计复位,服务端处理结果"点餐成功"打印在点餐机终端。
- **自动跟价**:后台保存新价格后,点餐机无需重启,数秒内自动刷新各卡片单价并重算合计。

### 2.2 商家后台(admin)

- **界面布局**:左右两栏面板,共用与点餐机一致的奶茶色系与顶部品牌栏(「管」logo +
  "茶小满 · 后台管理")。
- **价格设置(左栏)**:5 款奶茶各占一行,显示名称与当前价(¥),行内 [+]/[-] 按钮
  逐元调整(限 1~99 元);左栏底部"恢复默认"一键回到出厂价(尚未写入,需再保存),
  醒目的金黄"保存价格"按钮负责生效;左下角有绿色状态文字,保存成功显示
  "已保存 ✓",失败则提示原因。启动时自动载入上次保存的价格,找不到则用默认价并提示。
- **点餐信息(右栏)**:订单区每 2 秒自动检测新订单并追加显示,新订单自动滚动到底部;
  也可点右上角"立即刷新"按钮手动更新;列表内鼠标滚轮或按住拖动可上下翻阅历史订单,
  每条订单显示下单时间与所选饮品、数量、合计。

## 3. 系统框架

```
                 ┌────────────────────────────────────────────┐
                 │                数据文件(共享层)               │
                 │  my_server/milktea_prices.txt   ← 价格      │
                 │  my_server/order_list.txt       ← 订单流水   │
                 └───────▲──────────────────▲────────────────┘
                         │ 每 3s 轮询        │ 写/读
         ┌───────────────┴───────┐   ┌──────┴─────────────────┐
         │  client(点餐机)       │   │  admin(商家后台)        │
         │  LVGL 界面 1024×600   │   │  LVGL 界面 1024×600    │
         │  选品 → 提交订单 ──┐   │   │  调价 / 订单面板        │
         └──────────────────┼───┘   └────────────────────────┘
                            │  TCP 127.0.0.1:50021
                 ┌──────────▼───────────┐
                 │  server(服务端)       │   纯 C,多线程
                 │  accept 循环          │   每连接一个线程
                 │  链表管理在线客户端    │   解析 JSON → 落盘
                 └──────────────────────┘
```

协作方式:

| 链路 | 途径 | 说明 |
| ---- | ---- | ---- |
| client → server | TCP socket | 点餐机把订单明文发给服务端 |
| server → 文件 | 追加写 | 服务端解析后落盘 `order_list.txt` |
| admin → 文件 | 读写 | admin 改价写 `milktea_prices.txt`,订单面板读 `order_list.txt` |
| client ← 文件 | 轮询 | client 每 3 秒检测价格文件,自动跟随 admin 的改价 |

## 4. 设计方案

### 4.1 server(服务端)

主流程:`socket → bind(INADDR_ANY:50021) → listen → accept 循环`,每来一个连接
`pthread_create` 一个收包线程(`recvfunction`)。线程职责:

1. 记录客户端 IP/端口,尾插进全局链表(`add_tial`),在线数 +1(互斥锁保护);
2. 按连接打开 `order_list.txt` 的文件描述符(O_APPEND);
3. 循环 `recv`;由 `strtojson` 解析:自动分配自增 `client_id`,按 `\n`/`:` 切分拼 JSON;
4. 时间戳行 + JSON 整体追加落盘,回执"点餐成功";
5. 断开时链表摘除、释放 fd、在线数 -1(`release`)。

### 4.2 admin(商家后台)

UI 左右两栏:

- **左栏 · 价格设置**:每款一行 `[+]`/`[-]` 调价(1~99),"保存"把 5 行 `中文名=价格`
  整体写回价格文件;启动先读文件恢复,读不到用内置默认价;
- **右栏 · 订单面板**:只读 `order_list.txt`,2 s 定时器检查文件大小变化重载,可手动
  "立即刷新";新订单自动滚动到底部。

### 4.3 client(点餐机)

- 5 张饮品卡片点击 +1,卡上"−"减杯(下限 0),角标与底部合计条联动;
- **价格同步**:启动用内置默认表 `PRODS`;此后 3 s 定时器 `stat` 价格文件,大小变化才
  重读,按中文名匹配刷新单价并重算合计——admin 保存后点餐机无需重启即自动跟价;
- **提交订单**:已选饮品拼成 `英文key: 数量` 行 + `Total price: 合计` 行,一次 `send`。

### 4.4 关键设计决策

1. 单工程三程序:共用一份 CMake 与 LVGL 源码,server 不依赖图形库;
2. 路径全部编译期宏、集中管理,可 `-D` 覆盖;数据文件不入 git(见附录 B);
3. 价格以文件为唯一事实源:文件一旦可读即用文件值覆盖内置默认价;
4. 在线客户端单链表管理,增删与全局计数均加互斥锁,fd 用完即释放。

### 附录 E 实测验证与展望

实测(1 admin + 1 server + 多台 client,本机回环):

- 各 client 独立下单,server 终端实时打印每单,`order_list.txt` 按时间戳连续追加;
- admin 订单面板每 2 s 出现新订单并自动滚到底部;
- admin 调价保存后,client 卡片价格 3 s 内自动更新。

改进方向:

- 价格改由 server 经 socket 主动下发/广播,替代共享文件轮询,消除路径耦合与并发读写;
- `client_id` 多线程自增未加锁,高并发有计数竞态,可并入互斥保护;
- 落盘依赖 O_APPEND 原子性,可升级文件锁或独立存储;网络层无鉴权,仅适用内网教学。
